## 5. 이번 세션에서 알아낸 함정·구조 (재조사 방지)

### 내보내기에서 버려지는 섹션이 있다

`export/build.py` 의 `_SKIPPED_SECTIONS = {문제 확인, 검산}` — **`## 문제 확인` 은 docx/hwpx 에 나가지 않는다.**
그래서 오류 고지를 거기 쓰면 문서에서 사라진다. `3c7437d` 에서 오류 이유를 `## 풀이` 로 옮긴 이유가 이것이다. `## 오답 주의` 도 살아남는다.

### `content_rect` 는 크롭 영역과 공유된다

`extractor.py:774` 가 문항 크롭 좌표 계산에 쓴다(유형 문제집 경로 `:613` 도). **이걸 바꾸면 이미 올린 모든 시험지의 문항 이미지가 달라진다.** 14번에서 "본문 경계 수정" 안을 기각한 이유다.

### 풀이 경로는 판독본을 쓰지 않았다

`load_solve_targets` 는 `problems.text` 와 파일 `mode` 만 본다. 판독본이 DB 에 있어도 이미지로 푼다. `9812c26` 이 실패 시에만 그 구멍을 메웠다.

### 엉터리 풀이가 저장되면 다음 잡이 건너뛴다

`plan_solve_job` 이 `solved_numbers` 로 스킵한다. 재풀이는 "다시 풀기"(`force`) 없이는 안 된다.

### pdf.js 는 헤더 인증이 된다

`pdfjs-dist@5.7.284`: `types/src/display/api.d.ts:28` 의 `httpHeaders`, 구현은 `legacy/build/pdf.mjs`. **Range 리더도 `new Headers(stream.headers)` 로 복사한다**(`:19693`, `:19751`). 그래서 PDF 는 토큰이 필요 없고 만료·재로딩 문제가 구조적으로 없다.

### `service/` 는 죽은 사본이다

레포 루트 `service/extractor.py` 는 2026-07-31 자 구버전이고 **import 되지 않는다**(`import service` → `app/core/service.py`). 건드리지 마라.

### 배포 검증에서 놓치기 쉬운 것

- 프로덕션 번들 grep 시 청크 정규식에 **`/` 를 넣어야** `app/page-<hash>.js` 를 놓치지 않는다: `/_next/static/[a-zA-Z0-9._/-]+\.js`
- 백엔드는 `gh run list` → `gh api repos/hyunwoo-company/k8s-helm/commits` 첫 줄이 `chore(math-teacher-api): image sha-<HEAD>` 인지까지가 이 PC 에서 확정 가능한 범위다. **ArgoCD 실제 sync 는 관측 불가**(kubectl context 없음)

### 서브에이전트에게 `git stash` 를 금지하라

14번 에이전트가 포맷 대조용으로 `git stash`/`stash pop` 을 실행해, 동시에 진행 중이던 프론트 변경 8개 파일이 함께 stash 에 들어갔다 나왔다. `index.lock` 충돌로 커밋이 한 번 실패했다. 데이터 손실은 없었지만(점검 완료) 병렬 작업 중에는 위험하다. 대조가 필요하면 `git show HEAD:<path>` 를 쓰게 하라.

## 6. 작업 방식 (이 세션에서 굳은 것)

- **Advisor / Worker 분리** — 메인은 조사·브리프·검증·커밋·배포, 구현은 서브에이전트. 브리프에 **이미 조사한 컨텍스트(파일·라인·수치)를 담아** 재탐색을 막는다.
- **에이전트 보고를 그대로 믿지 않는다.** diff 와 테스트를 직접 돌려 확인한 뒤 커밋한다. 이번 세션에 이 방식으로 결함 2건을 잡았다(`compare_digest` non-ASCII → 500 / 정규식 `$` 의 끝 개행 허용).
- **에이전트가 내 판단을 반증하면 받아들인다.** 이번에 3건 정정했다 — `1+` 지수 "재현 안 됨" 오판(grep 패턴 오류), `sqrt` 잘림 가설(글리프 좌표로 반증), 프론트 테스트 기준선 수치 혼동.
- **추측으로 구현하지 않는다.** 불명확하면 보류하고 무엇이 필요한지 보고한다. 범위를 줄였으면 반드시 노션에 남긴다.
- **배포 순서**: 백엔드·프론트를 함께 바꿨으면 `app/core` 먼저 올리고 반영을 확인한 뒤 `app/web`. 하위호환을 남겨 중간에 깨지는 구간을 없앤다(`79f1efb` → `56b1e80` 가 그 예).
