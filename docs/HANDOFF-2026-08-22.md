### (a) 2단 조판 — 제목 전폭 (`8b3d8ed`, 처리 완료)

**사용자가 실물로 발견했다** — 제목이 좌측 단에 갇혔다. `w:cols` 가 구역 속성이라 구역이 하나면 문서 전체가 2단이고 그 안에 제목도 포함된다.

전폭으로 뺀 것 넷: `title` · `notice` · `_ANSWER_SECTION_TITLE` · `footer`. 규칙은 `model.full_width_flags()` 의 **"1수준 Heading 은 전폭"** 한 줄이다(`build.py` 는 안 바뀌었다). `PageBreak` 만 `None` 예외 — 내용 없는 지시라 속할 단이 없고 여기서 구역을 갈면 빈 구역이 생긴다.

- **docx**: 구역 5개(`1/2/1/2/1`), 나누기 전부 `continuous`. **모든 구역에 A4·여백을 걸었다** — 안 걸면 중간부터 Letter 로 돌아간다. `w:sep` 은 2단 구역에만(전폭에 남으면 한가운데 세로선이 그어진다)
- **hwpx**: `colCount` 가 `1/1/2/1/2/1`
- **빈 페이지 안 생긴다**: `python-docx` 의 `add_section` 은 구역 경계마다 빈 문단을 만드는데, `_split_section` 이 `w:sectPr` 만 직전 문단으로 옮기고 그 빈 문단을 지운다 → 문단 순서가 1단 렌더와 동일

## 5. 이번에 알아낸 함정·구조 (재조사 방지)

### pytest 를 두 개 동시에 돌리지 마라

**한 시간 넘게 멈춘다.** 이번에 실제로 겪었다 — 백그라운드로 띄운 것과 이후 실행이 겹쳐 `test_jobs.py` 37% 에서 정지했다. 개별 파일은 정상(`test_jobs` 17개 20초, `test_ocr` 15개 7초)이었고, 프로세스를 정리하고 하나만 돌리자 5분에 902개가 통과했다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -like '*pytest*' }
```

### 출력이 안 보여도 진행 중일 수 있다

Windows 리다이렉트는 버퍼가 커서 `tail` 이 갱신되지 않는다. `pytest -q` 의 최종 요약 줄이 안 찍히는 경우도 있다 — **`-o addopts=` 를 줘야** 나온다(`pyproject.toml` 의 `addopts = "-q"` 때문).

### 웨일 문서 뷰어는 hwpx 그림을 렌더하지 못한다

우리 파일은 정상이다(이미지 6장, `hp:sz` 유효, `binaryItemIDRef` 정상, `check_id_integrity` 로 dangling 0 / orphan 0). **폴라리스·한글에서는 보인다.** hwpx 확인은 웨일에서 [편집] → 폴라리스로 하거나 docx 로 하라.

### python-hwpx 6.0.2

- `HwpxDocument.set_columns` / `set_paragraph_format` 은 **deprecated**(7.0 제거). `doc.page.set_columns` / `doc.styles.apply_paragraph_format` 을 써라
- **`apply_paragraph_format` 은 부를 때마다 새 `paraPr` 을 찍는다.** 문단마다 부르면 434문항 문서의 `header.xml` 이 수천 개로 불어난다 → 자리마다 한 번만 찍고 참조를 재사용
- 페이지 나눔은 `add_paragraph("", pageBreak="1")` 로 통한다(`**extra_attrs` raw 통로)
- `NotesNamespace.add_endnote` 로 **진짜 미주도 만들 수 있다**
- `HwpxDocument.new()` 의 템플릿 metadata 가 `synthetic-fixture-author` 다(테스트용 합성 템플릿)

### rapidocr / opencv 배포 함정

`rapidocr-onnxruntime` 의 의존성은 **`opencv-python`(GUI 빌드)** 이고 그 휠은 Qt5 를 담아 `libGL.so.1` 등을 요구한다 → **slim 이미지에서 `import cv2` 가 즉시 깨진다.** Dockerfile 이 그것을 지우고 `opencv-python-headless` 로 바꿔 넣는다(apt 추가 0줄, 13MB 작다). **순서가 중요하다** — 반대로 하면 GUI 제거가 공유 `cv2/` 를 함께 지운다. 그래서 headless 를 `requirements.txt` 에 적지 않았다.

빌드 시점 `import cv2, rapidocr_onnxruntime; RapidOCR()` 연막 검사를 둬서 CI 에서 먼저 터지게 했다.

**numpy 는 배포 이미지에 없었다.** `pymupdf-1.28.0` 의 `Requires-Dist` 가 비어 있다 — 내가 "pymupdf 가 끌어온다"고 한 것은 틀렸다.

### 번호 리셋은 추출기가 처리하기도 한다

`_pick_anchor_chain` 이 **구획 리셋 사슬 vs 단조증가 사슬 중 긴 쪽**을 고른다.

- **풍문고**: 리셋이 잦아 리셋 사슬이 이김 → `_renumber_duplicates` 로 1~106 재매김 → **전부 잡힌다**
- **강대X**: 공통과목 1~22가 길게 이어져 단조증가가 이김 → 뒤 선택과목 23~30이 버려짐 → **29문항**

즉 **수능형 모의고사만** 과목별로 나눠 올려야 한다. 글자 있는 PDF 도 같다.

### OCR 좌표의 칼럼 판정 함정

강대X 는 595pt 폭이라 페이지 중앙이 297.5pt 인데 우측 칼럼 앵커가 **290~294.5pt** 에 있어 좌측으로 분류돼 통째로 탈락한다. 페이지별 스캔 오프셋이다(같은 페이지 좌측 앵커와 항상 약 257pt 차이). OCR 경로만 **읽어낸 글자의 x 범위 중앙**을 분기선으로 쓴다(`PageLayout` 주입).

### hw-01 이미지 정리 — pause 는 pinned 가 아니다

파드 샌드박스(pause)는 컨테이너가 아니라 `crictl ps -a` 에 안 나오고, 이 노드의 pause 는 **`pinned=false`** 다. pinned 플래그에 기대는 설계는 여기서 통하지 않는다 — 설정에서 직접 읽어야 한다.

`crictl rmi <id>` 는 그 id 의 **모든 태그**를 지운다. 태그 전수 일치(`all`)로 걸러야 한다 — 이 노드에 `fgg-server:latest` 와 `:sha-d9422c1` 이 같은 id 를 공유하는 실제 사례가 있다.

**이미지 생성 시각 필드가 CRI 에도 ctr 에도 없다.** content store 의 config blob mtime 을 pull 시각으로 쓴다.

## 6. 작업 방식

- **Advisor / Worker 분리.** 메인은 조사·브리프·검증·커밋·배포, 구현은 서브에이전트. 브리프에 **이미 조사한 실측값(파일·라인·수치)** 을 담아 재탐색을 막는다.
- **에이전트 보고를 그대로 믿지 않는다.** diff·테스트·회귀표를 직접 돌려 확인한 뒤 커밋한다.
- **에이전트가 내 판단을 반증하면 받아들인다.** 이번에 여러 건 정정했다 — 우측 칼럼 좌표 오판, numpy 가 이미 있다는 오판, 전체 이미지 개수, pause 의 pinned 여부, 브리프의 `==` 유지 불가.
- **추측으로 구현하지 않는다.** hwpx 2단 배치는 두 버전을 만들어 사용자가 실물로 고르게 했다.
- **커밋을 파일 단위로 나눌 수 있으면 나눈다.** 이번에 OCR / export / infra 가 겹치지 않아 세 커밋으로 갈랐다.
- **배포 순서**: `app/core` 먼저 → CI + helm 태그 확인 → `app/web`. 프론트 검증은 **번들 grep** 으로 한다(HTTP 200 은 근거가 아니다). 청크 정규식에 `/` 를 넣어라 — `/_next/static/[a-zA-Z0-9._/-]+\.js`
