# 문항 텍스트화 — PUA 디코딩 1차 + AI 비전 폴백

작성일: 2026-08-14
범위: 백엔드(`app/core`) + 프론트엔드(`app/web`).

## 1. 목적

내보낸 시험지·오답노트에서 문항을 **크롭 이미지 대신 텍스트로** 조판한다.
텍스트로 안전한 문항만 텍스트로 내고, 불가한 문항은 이미지로 낸다(**혼합**).

텍스트를 얻는 경로는 둘이고, **순서가 중요하다.**

1. **1차 — PDF 텍스트 레이어 디코딩.** AI 호출 0회. 결정적. 원본 글리프 그대로.
2. **2차 — AI 비전 판독.** 1차가 실패한 문항만.

## 2. 1차 경로가 가능하다는 근거 (2026-08-14 실측)

처음에는 "PDF 텍스트 레이어는 수식이 PUA 로 깨져 쓸 수 없다"고 판단했다. **그 판단은
틀렸다.** 실측으로 뒤집혔고, 이 절이 그 근거다.

### 2-1. 폰트에는 단서가 없다 (여기까지는 맞았다)

수식 폰트 `INPILL+HyhwpEQ`(글리프 67개)의 테이블:

```
cvt, fpgm, glyf, head, hhea, hmtx, loca, maxp, prep
```

`cmap` 없음(문자코드↔글리프 매핑 없음), `post` 없음(글리프 이름 없음).
`ToUnicode` 는 있지만 PUA(U+E000~)를 가리킨다.

### 2-2. 그러나 PUA 오프셋이 원본 글리프 순서를 보존한다

`오프셋 = 코드 - 0xE000` 으로 보면 값이 규칙적이다. 개포고 시험지에서 쓰인 오프셋:

```
0, 1, 15~18, 52~61, 68~72, 75, 82, 83, 85, 92, 109, 110, 157, 158, 229~254
```

1번 문항의 실제 원본(크롭 이미지를 읽어 확인)은 `A = 3x² − xy + y²` 이고,
그 문항의 PUA 시퀀스와 1:1 로 맞는다.

```
오프셋:  0   71   54  252  53   70  252 253  72  253  53
문자:    A   =    3    x   2    −    x   y   +    y   2
```

[leesj.me 의 HYHWPEQ 글리프 구성 분석](https://leesj.me/hwp-custom-equation/)이 말하는
배열("로만체 알파벳 / 각종 기호 / 다시 로만체 알파벳 / 이탤릭체 소문자 알파벳")과 일치한다.

**확정된 구간** (실측 대조로 확인):

| 오프셋 | 문자 | 확인 근거 |
|---|---|---|
| `0~25` | `A~Z` | 0=A, 1=B (두 다항식 A, B) |
| `52~61` | 숫자 `1,2,…,9,0` | 53='2', 54='3' 대조 확인. **0 부터가 아니라 1 부터다** |
| `68`, `69` | `(`, `)` | 4개 시험지 전부에서 **빈도가 정확히 같은 쌍** |
| `70`, `71`, `72` | `−`, `=`, `+` | 1번 문항 대조 확인 |
| `229~254` | **이탤릭** `a~z` | 229=a 기준 229+23=252=x, 최다 빈도(136회)가 x 와 일치 |
| `26~51` | 로만체 `a~z` (추정) | 배열 순서상. 실물 대조 필요 |

**미확정 구간** — 구현 시 크롭 이미지와 대조해 채워야 한다:
`15~18`, `75`, `82`, `83`, `85`, `92`, `109`, `110`, `157`, `158`, 그리고 `62~67`,
`73~92` 중 미확인분, `93~228` 중 사용되는 값.

### 2-3. 매핑표가 시험지 간 재사용된다 (결정적)

서브셋 폰트(`INPILL+` 접두사)라 글리프 인덱스가 재배열될 것을 우려했으나, **보존된다.**
서로 다른 4개 시험지 PDF 를 비교했다.

| 시험지 | 수식 폰트 | 최다 오프셋 | 68/69 빈도 |
|---|---|---|---|
| 개포고 | `INPILL+HyhwpEQ` | **252**(=x) | 124 / 124 |
| 풍문고 | `INPILL+HyhwpEQ` | **252** | 55 / 55 |
| 반배치고사 | `INPILL+HyhwpEQ` | **252** | 44 / 44 |
| 일일테스트 | `INPILL+HyhwpEQ` | 109 | 24 / 24 |

252 가 세 시험지에서 최다이고, 68/69 는 모든 시험지에서 정확히 같은 빈도의 쌍이다.
→ **매핑표를 한 번 만들면 재사용할 수 있다.**

### 2-4. 2차원 구조는 좌표로 복원된다

문자를 디코딩해도 지수는 문자열에 그냥 숫자로 들어온다. 그러나 PDF 는 글자마다
크기와 좌표를 준다(`page.get_text("rawdict")`). 1번 문항 실측:

```
'x'  size=8.9  y0=115.4    ← 본문
'2'  size=6.0  y0=113.7    ← 지수: 크기 0.67배, y0 상승
'-'  size=8.9  y0=114.9
'2'  size=8.9  y0=115.4    ← 계수(2xy): 크기·y 동일
```

지수와 계수가 **명확히 갈린다.** 아래첨자도 같은 원리(크기 작고 y 하강)다.
분수·근호는 **가로선이 그래픽 요소**로 들어오므로 `page.get_drawings()` 로 선을 찾아
위/아래 글자를 묶는다.

## 3. 설계

### 3-1. 1차: PUA 디코더 (`app/core/pua_decode.py`, 신규)

**입력**: PDF 페이지 + 문항 bbox. **출력**: LaTeX 문자열 + 신뢰도 판정.

```python
@dataclass(frozen=True)
class DecodeResult:
    latex: str | None        # 복원 실패면 None
    ok: bool                 # 신뢰할 수 있는가
    reason: str | None       # 실패/저신뢰 이유(로그·UI 표시용)
    unknown_offsets: list[int]  # 매핑표에 없던 오프셋(표 확장 단서)
```

단계:
1. `rawdict` 로 글자·크기·좌표를 모두 받는다.
2. PUA 문자는 매핑표로 치환한다. **매핑표에 없는 오프셋이 나오면 `ok=False`** 로
   내리고 그 오프셋을 `unknown_offsets` 에 남긴다(다음 표 확장에 쓴다).
3. 크기·y 로 지수/아래첨자를 판정해 `^{}` / `_{}` 를 만든다.
   기준선 그룹은 본문 크기의 다수결로 잡고, 0.8배 미만 + y 이동으로 판정한다.
4. `get_drawings()` 의 수평선으로 분수·근호를 재구성한다.
   - 선 위/아래에 글자가 모두 있으면 분수(`\frac{}{}`)
   - 근호 글리프 뒤에 오는 선은 근호의 덮개(`\sqrt{}`)
5. 괄호 쌍을 맞춰 `\left( \right)` 로 감싼다.
6. 다음이면 `ok=False`: 미확인 오프셋 존재 / 선 구조를 못 묶음 / 괄호 짝 안 맞음 /
   글자 없음 / 그림·표로 보이는 그래픽 요소 다수.

**보수적으로 판정한다.** 잘못 복원한 문제를 내보내는 것이 이미지로 내보내는 것보다 나쁘다.

매핑표는 `app/core/pua_table.py` 로 분리한다(데이터와 로직 분리, 표 확장이 쉬워야 한다).
표에는 확정 근거를 주석으로 남긴다.

### 3-2. 2차: AI 비전 폴백

1차가 `ok=False` 인 문항만 AI 에 보낸다. 작업 종류 `kind="transcribe"`.

응답 형식:

```
## 판정
가능 | 불가
(불가면 이유 한 줄: 좌표평면·그래프 / 도형 / 표 / 판독 불가)

## 문제
(가능일 때만) 원본을 글자와 수식 그대로 옮긴 전문.
발문, 선택지 ①~⑤, 배점, (가)·(나) 조건 상자를 빠짐없이.
수식은 기존 LaTeX 규칙(`\( \)`, `\[ \]`).
```

`prompts.py` 에 `TRANSCRIBE_SYSTEM_PROMPT` 를 넣고 기존 공유 스킬을 재사용한다.
**풀이를 쓰지 말고 문제만 옮기라**고 명시한다. 애매하면 `불가` 다.

별도 OCR 패키지(Tesseract/pix2tex/Mathpix)는 도입하지 않는다 — 1차 디코딩이 더 정확하고,
2차는 이미 있는 AI 비전으로 충분하다.

### 3-3. 저장

`problems` 에 세 열을 더한다(스키마 버전 올림, 기존 행 NULL).

```sql
ALTER TABLE problems ADD COLUMN transcript TEXT;         -- LaTeX 전문
ALTER TABLE problems ADD COLUMN transcript_source TEXT;  -- 'pua' | 'ai' | 'manual'
ALTER TABLE problems ADD COLUMN transcript_note TEXT;    -- 실패/불가 이유
```

- `transcript_source` 를 남기는 이유: 디코딩본과 AI 판독본은 신뢰도가 다르다.
  화면에서 구분해 보여주고, 사용자가 고친 것(`manual`)은 재실행이 덮지 않는다.
- 오답노트는 `note_items.transcript` 를 더해 담을 때 **스냅샷 복사**한다(크롭 스냅샷과 같은 규칙).
- `reextract` 는 문항 번호가 바뀔 수 있으므로 `transcript` 도 함께 지운다.

### 3-4. 내보내기

쿼리 파라미터 `body` 를 더한다.

```
body=image (기본) : 지금과 완전히 동일
body=text         : transcript 가 있으면 텍스트, 없으면 이미지로 조용히 폴백
```

`build.py` 의 `ExamItem`/`NoteItem` 에 `transcript: str | None` 을 더한다.
텍스트로 나간 문서는 첫 페이지에 한 줄 고지를 넣는다.

> 이 문서의 문항은 원본 PDF 에서 복원한 것입니다. 배포 전 원본과 대조하십시오.

`transcript_source` 가 `ai` 인 항목이 하나라도 있으면 고지 문구에 "일부는 AI 판독본"을
덧붙인다. 전부 `pua`(디코딩)면 그 사실을 밝힌다 — 신뢰도가 다르므로 정직해야 한다.

수식은 2026-08-14 에 넣은 수식 개체 조판(`export/omml.py`, `export/hwpeq.py`)을 그대로 탄다.

### 3-5. 화면

- `[풀이]` 탭에서 문항을 펼치면 크롭 이미지와 복원 텍스트를 **나란히** 보여준다
  (좁으면 위아래). 출처 배지(`디코딩` / `AI 판독` / `직접 수정`)를 붙인다.
- 복원 텍스트는 **편집 가능**하다. 저장하면 `transcript_source='manual'`.
- 실패한 문항은 이유를 배지로("그래프 포함 — 이미지로 내보냄").
- 상단에 진행 표시와 중단. **변형에서 배운 규칙을 지킨다** — 진행 상태의 단일 소스는
  저장된 값이고 새 집계 상태를 만들지 않는다.
- `ExportButton` 에 `☐ 문항을 텍스트로` 체크박스. 판독본이 없으면 비활성 + 이유 안내.
  마지막 선택을 `localStorage` 에 기억한다.

## 4. 구현 순서

| 순서 | 항목 | 범위 |
|---|---|---|
| 1 | 매핑표 완성 + PUA 디코더(문자·지수·아래첨자) | 백엔드 |
| 2 | 디코더 확장(분수·근호·괄호) + 신뢰도 판정 | 백엔드 |
| 3 | 스키마 3열 + `transcribe` 작업(1차 디코딩, 실패분만 AI) | 백엔드 |
| 4 | 내보내기 `body=text` + 고지 + 오답노트 스냅샷 | 백엔드 |
| 5 | 화면 대조·편집·진행 + 내보내기 체크박스 | 프론트 |

1~4 를 올려도 `body` 기본값이 `image` 라 기존 동작이 그대로다.

## 5. 하지 않는 것

- **별도 OCR 패키지 도입** — 1차 디코딩이 더 정확하고 2차는 기존 AI 비전으로 족하다.
- **판독 승인 강제** — 확인하지 않아도 내보낼 수 있다. 대신 고지와 대조 화면을 준다.
- **그림·그래프를 텍스트로 묘사** — 불가 판정이면 이미지로 낸다.
- **자동 실행** — 업로드 시 자동으로 돌리지 않는다. 1차는 AI 호출이 없어 싸지만,
  2차 폴백이 문항 수만큼 호출을 낼 수 있으므로 사용자가 명시적으로 실행한다.
- **HyhwpEQ 외 수식 폰트 대응** — 다른 폰트(HancomEQN 등)가 나오면 매핑표가 없으므로
  1차가 실패하고 2차(AI)로 간다. 그 경로가 이미 안전망이다.
- **행렬·여러 줄 수식 복원** — 1차에서 폴백 대상. 2차 AI 가 처리한다.
